Forwarded an optional `idempotency_key` from `CdpEvmWalletProvider.send_transaction`/`native_transfer` to the CDP SDK. The SDK already accepts the parameter, but the provider did not pass it, so an agent retry after a lost or ambiguous response submitted a second, independently valid transfer of the same value. Callers that retry the same logical transfer should pass the same key; when no key is supplied the behaviour is unchanged.
